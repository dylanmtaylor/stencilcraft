# StencilCraft UI specs

Executable Gherkin specs for the UI-first scope: Geometry, Operations, the
Inspector, menus and operation assignment. Each scenario is driven through the
real `egui` widgets with `egui_kittest`; assertions check both the visible
accessibility tree and the engine document.

The runner lives in [`../src/specs.rs`](../src/specs.rs) and reuses the harness in
`mod ui_e2e` (`../src/main.rs`). It adds no dependencies and runs under
`cargo test`.

## Running

```sh
# Baseline scenarios only (gaps skipped):
cargo test -p stencilcraft --bin stencilcraft specs

# Baseline + @gap scenarios; also rewrites specs/GAPS.md:
SPEC_INCLUDE_GAPS=1 cargo test -p stencilcraft --bin stencilcraft specs
```

`@gap` scenarios describe UI that does not exist yet. With gaps included they
are expected to fail; each failure is copied into [`GAPS.md`](GAPS.md) with the
step that could not find its widget. A gap that starts passing is listed under
"Closed gaps" so it can be promoted (remove the `@gap` tag).

## UI review gate

Gherkin checks the accessibility tree and the engine, not the pixels. Before and
after a UI change, capture the affected surface and look at it:

```sh
./target/debug/stencilcraft --control 7979 examples/starter.stencilcraft &
python3 - <<'PY'
import json, socket
s = socket.create_connection(("127.0.0.1", 7979))
s.sendall(json.dumps({"id": 1, "method": "app.screenshot",
                      "params": {"path": "/tmp/stencilcraft-ui/after.png"}}).encode() + b"\n")
print(s.makefile().readline())
PY
```

Open the PNG and check columns, alignment, spacing and footer placement against
the requirements. The gate is mandatory: a UI task is not done on green specs
alone (AGENTS.md).

## Writing a scenario

The user describes behaviour conversationally ("cuando pincho el martillo en la
fila del grupo, debe crear una operación con esas formas"). The agent translates
it into a `.feature` scenario and, when needed, a step mapping in `specs.rs`.
Find the widget with CodeGraph first (`geometry_panel`, `operations_panel`,
`inspector_panel`, `menus`) and record the phrase in [`locators.md`](locators.md).

Rules:

- Steps talk about what the user sees and does, not about private functions.
- Prefer a row's visible label (`#1`, `outer`, `cut`) or a button label over
  indexes.
- Assert both sides when it matters: the UI (`... is on screen`,
  `the geometry panel shows ...`) and the document (`the last operation has
  members 1, 2, 3`).
- Tag scenarios with the requirement ids from
  [`rustfactor/.planning/REQUIREMENTS.md`](../../../../../rustfactor/.planning/REQUIREMENTS.md)
  (`@GEO-04`, `@UI-05`, …).
- If the UI is missing, write the scenario anyway and tag it `@gap`.

## Step vocabulary

Given:

- `a document with N shapes`
- `a nested fixture with groups "outer" and "inner"`
- `all groups are expanded`
- `the unassigned group is expanded`
- `the bulk confirm threshold is N`
- `shapes 1, 2 are selected`
- `shape 1 is selected`
- `group 2 is selected in the geometry panel`
- `the inspector panel is open`
- `the workspace is open` (lists + inspector)
- `the menu bar is open`

When:

- `I hammer the geometry row "outer"`
- `I click the geometry row "#2, #1"`
- `I open the tag overflow for shape #1`
- `I remove shape #1 from the last operation`
- `I hide every operation of shape #2 from the geometry view`
- `I show every operation of shape #2 from the geometry view`
- `I click "Ungroup selected"`
- `I choose "Remove #1 from cut"`
- `I click the first operation row`
- `I click the "Settings" button for operation 1` (gap scenarios)
- `I open the "Panels" menu`

Then:

- `the document has N operations` / `the document has N groups`
- `the last operation has kind "cut"`
- `the last operation has members 1, 2, 3`
- `operation 2 has members 1, 2, 3`
- `operation 1 is visible` / `operation 1 is locked`
- `operation "cut" has 3 members`
- `the operations panel shows "Pass 2"`
- `the geometry panel shows "#3, #1 #2"`
- `the geometry panel does not show "#2, #1"`
- `the selected shapes are 1, 2`
- `"Create 3 operations?" is on screen`
- `the inspector shows the header "Shape #1 - Path"`
- `the inspector shows the operation "cut"`

Adding a step is a small `match` arm in `specs.rs`; keep it declarative.

## Scope note

The legacy document-level "Layers" section (Add Layer, Send to Layer…) is still
present beside Operations. Its fate is decided after the first spec run, with
`GAPS.md` as evidence.
